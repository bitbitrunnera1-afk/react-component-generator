# TDD 규칙

> **이 규칙은 Rigid — 상황에 맞게 변형하지 마라.** 예외가 필요해 보여도 아래 적용 기준에 따라 판단하고, 기준 자체를 바꾸지 마라.

## 1. 적용 기준

### 반드시 TDD를 적용한다

- **비즈니스 로직**: 조건 분기, 계산, 상태 전이, 검증 규칙
- **API**: 라우트 핸들러, 요청/응답 처리, 에러 매핑 (예: `server/index.ts`의 `/api/generate`)
- **유틸리티**: 순수 함수, 문자열/데이터 변환 (예: `server/generator.ts`의 `stripCodeFences`)
- **버그 수정**: 수정 전에 버그를 재현하는 실패 테스트를 먼저 쓴다

### TDD가 불필요하다

- **타입 정의**: 인터페이스, 타입 별칭 (예: `src/types/index.ts`)
- **설정 파일**: `vite.config.ts`, `tsconfig*.json`, `eslint.config.js`, `package.json`
- **순수 UI**: 표시만 하는 컴포넌트, 스타일 변경 (단, 동작이 있는 UI는 대상이다)
- **SQL**: 스키마와 마이그레이션. 로직이 담긴 쿼리는 검증 대상이다.

경계가 애매하면 **동작이 있으면 적용, 선언만 있으면 불필요**로 판단한다.

## 2. RED-GREEN-REFACTOR 사이클

### RED: 실패하는 테스트 작성

- **하나의 동작 = 하나의 테스트.** 여러 동작을 한 테스트에 묶지 않는다.
- 테스트를 쓴 뒤 **반드시 실행해서 실패를 확인한다.** 실행하지 않은 실패는 실패가 아니다.
- 실패 이유는 **"기능 미구현"** 이어야 한다. 오타, import 오류, 잘못된 설정으로 실패한 것은 RED가 아니다. 고친 뒤 다시 실행한다.

### GREEN: 최소 코드로 통과

- 테스트를 통과시키는 **최소한의 코드만** 쓴다.
- **YAGNI**: 지금 테스트가 요구하지 않는 분기, 옵션, 추상화를 넣지 않는다.
- 실행해서 **신규 테스트와 기존 테스트가 모두 통과**하는지 확인한다. 기존 테스트 실행은 `bun run test`로 한다.

### REFACTOR: 구조 정리

- 중복 제거, 이름 개선, 헬퍼 추출을 한다.
- REFACTOR 중에도 **테스트는 계속 초록(green)** 이어야 한다. 깨지면 되돌린다.
- **새 동작을 추가하지 않는다.** 새 동작이 필요해지면 REFACTOR를 멈추고 RED로 돌아간다.

### 반복

- 다음 동작에 대한 RED로 돌아간다. 한 사이클은 짧게 유지한다.

## 3. 삭제 강제 규칙

- 테스트보다 **프로덕션 코드를 먼저 작성했다면 그 코드를 삭제**하고 RED부터 다시 시작한다.
- 삭제한 코드를 **"참고용"으로 남기는 것은 금지**한다. 복사해서 되살리는 것도 같은 위반이다.
- 삭제를 되돌리는 것은 금지다. 테스트가 먼저 실패해야 구현이 시작된다.

## 4. 변명 차단표

| 변명 | 반론 |
|------|------|
| "너무 단순해서 테스트가 필요 없다" | 단순한 코드도 경계값과 분기에서 깨진다. 단순하면 테스트는 1분이면 쓴다. |
| "나중에 테스트를 추가하겠다" | "나중"은 오지 않는다. 구현을 확인하는 테스트는 구현을 본 뒤에 쓰면 구현을 그대로 따라 한다. 실패를 본 적 없는 테스트는 아무것도 증명하지 않는다. |
| "시간이 없다" | 테스트 없이 만든 코드를 디버깅하는 시간이 더 든다. 시간이 부족할수록 RED를 짧게 가져간다. |
| "삭제하면 낭비다" | 이미 쓴 코드는 검증되지 않은 상태다. 테스트를 나중에 붙이면 검증 없이 넘어간 코드가 된다. 삭제 후 재작성은 보통 몇 분이면 끝난다. |
| "이건 프로토타입이다" | 프로토타입은 버려지지 않고 결국 제품 코드가 된다. 프로토타입이라도 동작 단위 테스트는 같다. |

## 5. 프로젝트별 규칙 우선 조항

- 프로젝트의 `CLAUDE.md`, `AGENTS.md`에 TDD 규칙이 **있으면 그것을 우선**한다.
- 이 파일은 **기본값(fallback)** 이다. 프로젝트 규칙이 없거나 침묵하는 부분에만 적용한다.
- 프로젝트 규칙이 이 파일과 충돌하면 프로젝트 규칙을 따르고, 충돌 사실을 사용자에게 알린다.
